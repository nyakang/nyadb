# MyGo v0.7.4 Fork 升级（2026-11-05）

## 版本与发布

- 上游基线：[egoist/mygo v0.7.4](https://github.com/egoist/mygo/releases/tag/v0.7.4)，2026-11-01 发布，固定提交 `9bd34e1eb9525d9a1fe698aadc964c49c8ff8e7e`。
- 定制分支：[nyakang/mygo nyadb/v0.7.4](https://github.com/nyakang/mygo/tree/nyadb/v0.7.4)；已发布新的不可变标签 [v0.7.4-nyadb.1](https://github.com/nyakang/mygo/tree/v0.7.4-nyadb.1)，对应提交 `417b03725c71d996a88c36cc908be588d3e1d16b`。
- Fork `main` 从 `2b66322aa3355057c44317a1c510bb24946b8fa5` 快进同步至上游快照 `b3efd4b6b3a7f5754a4e95fa8e3da2ad5eb3237e`；main、定制分支和新标签原子推送，历史标签保持不变。
- NyaDB 从 `v0.7.3-nyadb.2` 升级，Go 保持 1.27.3，其他直接／间接依赖版本不变。模块与 import 路径保持兼容。

```go
go 1.27.3
require github.com/egoist/mygo v0.7.4
replace github.com/egoist/mygo => github.com/nyakang/mygo v0.7.4-nyadb.1
```

普通开发工作区 `go.work` 已移除旧研究 Fork 的替换，只保留 `use .`；历史研究目录保留。
发布后的回归测试、静态检查、工具和构建显式使用 `GOWORK=off` 与
`GOFLAGS=-mod=readonly`。`go tool mygo version` 返回 `mygo 0.7.4`。

默认模块缓存和独立空缓存均下载了新标签，两个校验和一致：

```text
github.com/nyakang/mygo v0.7.4-nyadb.1 h1:ZyMyf2ZaYghQm0+EcFk2wNCWdect/WA0vHe1G+SILdU=
github.com/nyakang/mygo v0.7.4-nyadb.1/go.mod h1:dVav53PwF2xEotjf4oA5lTY2Jp2exgzyjLhbSXhbMwE=
```

两个下载目录的 1527 个 Go 源码／模块文件与发布提交逐字节一致，文件集合也一致。
打包程序的 `go version -m` 显示远端 `v0.7.4-nyadb.1` 和上述真实校验和。

## 定制补丁与兼容性

完整移植 `.2` 的多行元数据表头、COMMENT 提示、离散选列、独立表头菜单、
单元格点击回调、条纹与网格、导航树三角／整行选中／展开区右键菜单和
Windows 紧凑菜单。保留 v0.7.4 的局部主题、输入处理、编辑菜单可用状态和
原生窗口首帧更新，NyaDB 业务代码与存储格式无需调整。

Windows `menudraw.go` 存在移植冲突，已将紧凑尺寸和字号策略接入上游新的
`itemWidth`／`learnMenuExtra` 算法。保留每个菜单项的测量宽度和 DPI、实测
额外宽度补偿，以及系统字体变化时的补偿失效逻辑；不恢复旧
`SM_CXMENUCHECK` 扣减。新增 Windows 回归检查两种密度、不同菜单／DPI、
部分重测、最小补偿及字体失效，已交叉编译，该用例仍需 Windows 实机执行。

新的完整可移植补丁：[mygo-v0.7.4-nyadb.1.patch](patches/mygo-v0.7.4-nyadb.1.patch)。
它基于精确上游提交，包含生产代码、回归、维护说明、表头 API 文档和 Go 标签的
npm 发布排除规则。22 个变更文件在独立基线工作区重建后与发布提交逐字节一致。
MIT 许可证及原有资产来源保留，补丁不包含研究截图或数据库数据。
历史 `.2` 补丁和重建脚本保留其原版本含义。

```sh
git clone https://github.com/nyakang/mygo.git temp/mygo-v0.7.4-rebuild
git -C temp/mygo-v0.7.4-rebuild checkout --detach 9bd34e1eb9525d9a1fe698aadc964c49c8ff8e7e
git -C temp/mygo-v0.7.4-rebuild apply --check "$PWD/docs/patches/mygo-v0.7.4-nyadb.1.patch"
git -C temp/mygo-v0.7.4-rebuild apply "$PWD/docs/patches/mygo-v0.7.4-nyadb.1.patch"
```

NyaDB 生命周期 race 使用筛选
`Test.*(Cancel|Close|Generation|Late|Park|Disconnect|Recovery|Lease)`，覆盖仓库规定的
contract、connections、localdb、dbruntime、engines、mysql 和九个 UI 功能包。
数据工作区排除 `TestDataTransfer|TestDataImport`。shell 的全部 28 个匹配顶层
用例按四个一组分成七批，每批退出 0；完整用例列表和结果见
`shell-race-results.json`。数据网格范围使用
`Test.*(Header|Column|Layout|Selection|Copy|Paste|Fill|Edit|Save|Draft|Inspector)`，
排除传输／导入压力测试及已单独验证的生命周期用例。

最初几条长命令收到 SIGTERM，退出 143。其原始日志保留在
`fork-test.log`、`nyadb-candidate-race.log` 和
`nyadb-shell-lifecycle-race-confirmed.log`，不计为完整命令通过。
最终 Fork 全量命令、功能包定向 race、数据网格 race 和 shell 七批均正常完成；
没有提高测试超时或改动生产生命周期代码。

Linux 工作流使用仓库已有原生 Shell 夹具、独立 Xvfb／Openbox 和可丢弃 SQLite，
验证中英文的 1280／840 像素数据网格、记录表单、SQL 结果／快照／字段查看／
缓存导出以及表设计页。两种语言的夹具文件 SHA-256 前后一致，拥有的进程全部停止。
文件位于 `native-workflow/{zh-Hans,en}/`；这是原生工作流证据，连接与打开工作区
由夹具命令触发。另从已打包正式程序和全新独立配置启动 NyaDB，截图首窗并
通过 Alt+F4 正常退出，结果位于 `formal-native/verification.json`。
该独立环境的系统密钥服务不可用，正式程序显示工作区保存不可用提示；这项
冒烟验证覆盖首窗绘制和正常关闭，未验证真实系统密钥保存。

一般 MyGo e2e harness 的额外尝试因启动时创建 webview、而本机缺少 WebKitGTK
失败，原始记录为 `fork-native-linux.log`，未计入 PASS。
Windows／macOS 桌面未实机验证；未启用需要独立服务器夹具的 MySQL／PostgreSQL
集成标志。编译与定向 race 结果仅适用于上述记录范围。

基线和 Fork 使用相同 Go 版本、`-buildvcs=false`、`-trimpath`、
`mygo_noinspector`、stripped 符号及 `production=1`；Windows 同时使用 windowsgui。

`nm -size`／`-dumpdep` 确认 counter 未链接 `pointerCellClick` 或网格绘制机器码。
共用行输入保留少量条件派发（Linux／Windows／Darwin 分别 150／160／144 字节），
