# MySQL 密码保存修复（2026-10-25）

## 原因

连接编辑器此前用临时变量渲染“保存密码”复选框并强制禁用。SQLite 档案模型有意不包含密码，关闭编辑器又会清空临时密钥，因此“确定”无法保存密码，也无法在重开后恢复。

## 独立实现（I）

- 启用 MySQL“保存密码”勾选框；通过操作系统凭据服务保存，**不在** `config.sqlite`、连接档案 JSON、日志或源码中写入明文。
- Linux 使用桌面 Secret Service／D-Bus（需要可用且解锁的密钥库），Windows 使用 Credential Manager，macOS 使用 Keychain；无凭据服务时**不**回退到明文文件。
- 按连接档案 ID + 配置名称隔离主配置、备用配置；重新编辑时恢复勾选状态和密码框内容（仍为遮罩输入）。切换配置可保留各自尚未保存的输入，取消窗口不修改系统凭据。
- 新建连接勾选“保存密码”后写入系统密钥库；编辑后支持更新、取消勾选删除、修改配置名称时迁移以及删除连接时清理对应凭据。
- 建立 MySQL 会话时：若本次密码输入框非空，优先使用临时输入；否则按活动连接配置尝试读取已保存密码。会话启动后清空临时输入。
- 独立保存元数据与凭据；凭据写入失败会提示并尝试还原元数据，多个凭据变更失败时尝试恢复此前的密钥库值。系统密钥库没有跨服务事务，回滚也可能失败，此时错误会明确显示。
- 原本只在当前窗口或会话中使用的 SSH／HTTP／SSL 私密字段**未**纳入此次保存，不能误认为已经安全持久化。

## 验证与边界

- 自动化：系统密钥库 API mock、连接创建与保存、重开编辑、取消不写入、去勾选删除、主／备用配置隔离、配置重命名、建立会话使用已保存密码、存储失败回滚、密钥库不可用时普通连接资料仍可编辑。
- 以 Go/MyGo 的真实代码路径及无窗口 `ui.NewTester` 测试为 I 证据。
- **Unknown：**尚无 Windows/macOS 实机系统凭据授权弹窗和 Linux 图形桌面密钥库交互的截图证据；静态编译通过不等于真实 UI/系统密钥库差分通过。
- 本轮未验证 Navicat 对密码持久化的内部存储方式，也未复制它的资源或实现。
