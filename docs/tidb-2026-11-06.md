# TiDB support and verification — 2026-11-06

NyaDB supports TiDB as an independent connection product, using the existing MySQL protocol adapter and shared workspaces. The supported baseline is TiDB 8.5+. Verification uses TiDB **8.5.3 with real PD and TiKV**, verified SQL TLS, and a dedicated disposable account.

## Connections and workspaces

- The chooser, native connection editor, navigator filter and brand icon identify TiDB independently. The default port is **4000**; connection URIs use `tidb://`.
- MySQL-family alternative configurations, SSL, SSH, HTTP gateway settings, transient passwords, vault rollback and asynchronous connection checks are retained. The persisted profile kind is `tidb`; existing MySQL/MariaDB storage formats and schema versions remain compatible.
- Connection tests and session publication read `VERSION()` and validate the TiDB release component, rather than its MySQL protocol version prefix. Ordinary MySQL/MariaDB servers and TiDB releases below 8.5 are rejected for TiDB profiles.
- Sessions, SQL leases and qualified catalog/object identities use the existing runtime generation boundary. Disconnect preserves SQL text and requires explicit recovery. Old handles cannot route work to a replacement session.
- Table data uses the sole shared data document and grid: keyset/offset paging, filters, sorting, count, field previews, exact decimal and binary values, editing, conflict detection, import/export and analysis. Complete field reads and drafts retain existing size limits.
- Grid writes bind private connections to pessimistic mode for locking reads and READ COMMITTED, independently of the server's global transaction-mode default. SQL documents can execute explicit optimistic or pessimistic transactions. Neither mode is automatically replayed after uncertain acknowledgements.

## Objects, DDL and administration

| Feature | TiDB behavior |
| --- | --- |
| Metadata | Tables, views and sequences; full `SHOW CREATE SEQUENCE` definitions and exact signed bigint parameters. Sequence documents are read-only. |
| Plans | `EXPLAIN FORMAT=tidb_json`, parsed into a neutral hierarchy with available estimates. Truncated, invalid, duplicate and excessively large/deep plans are rejected. |
| Table designer | Create/alter, supported fields, primary and ordinary indexes, visibility, foreign keys and CHECK constraints. TiDB ALTER steps are separated when a single statement would change the same key multiple times. Each acknowledgement and final definition is retained. |
| TiDB DDL attributes | Executable `/*T!…*/` attributes, including clustered keys and AUTO_RANDOM, are preserved and checked after reload. Unsupported edits to these attributes fail before execution. Standard version comments for index visibility and CHECK enforcement retain their meaning. |
| CHECK | TiDB disables CHECK by default. Designer/copy/restore execution checks `@@GLOBAL.tidb_enable_check_constraint` on the executing connection before mutation. When disabled, the operation is rejected and drafts are retained. NyaDB does not change this global variable. Unsupported inline CHECK additions through ALTER COLUMN are rejected. |
| Views | Full definitions, create/alter/drop through the existing reviewed object operations. |
| Accounts | User/role creation, password changes, lock/unlock, grants, role assignment/revocation and deletion. Privileges for unsupported routine/event/trigger/lock semantics are rejected. Passwords remain absent from operation receipts. |
| Maintenance | `ANALYZE TABLE` and `ADMIN CHECK TABLE`, with TiDB's acknowledged empty-result behavior handled explicitly. MySQL OPTIMIZE/REPAIR actions are unavailable. |
| Unsupported objects | Stored routines, triggers and events are neither advertised nor offered for TiDB; direct management requests reject them. Unsupported spatial, FULLTEXT, HASH/RTREE and descending index semantics are rejected by the designer. |

TiDB's `SHOW WARNINGS` lacks MySQL's LIMIT syntax. All returned warnings are checked; only the recognized prepared-plan-cache diagnostic is excluded from exact-value rejection. Other warnings still reject the edit batch. Numeric/boolean default quoting and integer display widths are normalized without hiding changes to types, unsignedness or values.

## Backup and restore

TiDB retains NyaDB's version 1 archive format and full public DDL. Table rows use a consistent snapshot; foreign keys are restored after tables/data and sequences before dependent tables. TiDB-specific executable comments remain intact through copy, dump and restore verification.

TiDB archives require TiDB targets, and TiDB targets require TiDB archives. Ordinary legacy MySQL/MariaDB archive compatibility remains intact. Unsafe schema remapping inside executable comments is rejected before mutation.

**Sequence backups contain definitions only.** Allocated/current sequence values are not captured; restoring restarts at the definition's `START WITH`. This limitation is recorded in archive warnings and SQL dumps. These backups must not be used to continue sequence allocation without an explicit application-level reconciliation.

## Verification

`tools/verify_tidb_fixture.py` creates uniquely labelled PD, TiKV and TiDB containers on an isolated network, exposes SQL/PD ports only on loopback, creates temporary certificates and a random TLS-only account, runs integration tests, and removes its own resources. Cleanup verifies ownership labels and uses immutable container/network IDs. Credentials and fixture environments stay in ignored private temporary directories.

```sh
python3 tools/verify_tidb_fixture.py
NYADB_TIDB_RACE=1 python3 tools/verify_tidb_fixture.py
CGO_ENABLED=0 go test ./...
go test -race ./internal/db/contract ./internal/services/connections ./internal/storage/localdb ./internal/services/dbruntime ./internal/services/engines ./internal/services/mysql ./internal/ui/shell ./internal/ui/connectioncatalog ./internal/ui/connectioneditor ./internal/ui/navigation ./internal/ui/sessionbrowser ./internal/ui/sqlworkspace ./internal/ui/dataworkspace ./internal/ui/objectworkspace ./internal/ui/theme
CGO_ENABLED=0 go vet ./...
go tool mygo vet
go tool mygo i18n check
python3 -m unittest discover -s tests -v
```

The integration suites cover version/TLS identity, table/view/sequence metadata, typed paging, bounded fields, edits/conflicts, transactions against optimistic defaults, both SQL transaction modes, imports, analysis, TiDB plans, CHECK OFF/ON, accounts/roles/grants, foreign keys, invisible-index replacement, table/view design, copy, backup/restore, sequence warnings, cross-product restore rejection, maintenance, query cancellation and original-session revocation.

Shell tests exercise chooser/editor identity in Chinese and English, real connection and database activation, native table creation, grid editing, sequence documents, SQL execution and disconnect/recovery. Images and logs are written to ignored `build/tidb/`, including `zh-Hans-tidb-editor.png`, `en-tidb-editor.png`, `tidb-live-designer.png`, `tidb-live-grid.png`, `tidb-live-sequence.png`, `tcp-tls-verification.log` and `race-verification.log`. Linux amd64, Windows amd64 and macOS arm64 builds use `CGO_ENABLED=0`.
