在[私有 DPI 会话边界](dameng-dpi-boundary-2026-11-07.md)上增加显式远程
端点和 Go 负责的服务器证书身份校验，修正原厂客户端超时单位。达梦

## 实际传输与信任

调用方自行安装已验收的原厂 DPI 客户端、OpenSSL 依赖和证书；应用没有
下载、打包或重新分发厂商文件。原有三个 Linux amd64 客户端摘要不变。
每次物理连接仍只拨号一次，Go 持有原始上游 socket，不重连或重试。

显式 `TLSOptions` 支持 `verify-full`（默认）、`verify-ca`、`require` 和
`disable`。完整校验验证原始服务器证书链及配置的服务器名称；CA 校验
验证链，允许不检查名称。`require` 是调用方明确选择的加密策略；提供 CA
时仍校验链。禁用 TLS 必须明确指定，且拒绝证书和服务器名称设置。
省略整个 TLS 策略时保留原来的 loopback-only 验收模式。

只解析实际 DPI 客户端的初始原生 greeting：64 字节头、最多 64 KiB
正文和初始消息类型。正文不改写；当前只接受原生 `ENABLE_ENCRYPT=1`
或明确禁用时的 `0`。证书认证但不加密的 `2`、未验收的 `4/5`、TLCP
以及未知模式明确拒绝，没有明文回退。

远端 TLS 至少为 TLS 1.2。Go 完成原始服务器校验后，才向 DPI 交付
服务器的 greeting，允许原生认证继续。DPI 与 Go 之间另用每个物理会话
独有的临时 CA、服务端和客户端证书保护 loopback socket；该本地通道
确实要求和验证客户端证书，当前为已验收的 TLS 1.2。临时目录为 `0700`，
证书和私钥为 `0600`，原生句柄和转发线程退出后清理。

模式 1 要求调用方显式提供客户端证书和私钥，Go 确认原始服务器实际
请求过该身份。指定身份不会因为服务器的 issuer 列表不匹配而被静默
省略。这些措施不能替代数据库服务器自身的客户端证书验证。

## 超时与重复握手

2026 客户端的原始系统调用证明，DPI 登录及连接 I/O 超时属性 `103/113`
使用毫秒；此前直接传入秒数 `10`，实际形成了 10 毫秒 socket 超时，
使原生客户端偶尔在 Go 完成远端 TLS 验证前退出。现在按毫秒设置这两个
属性，语句查询超时继续按秒设置，Go 的原始 socket 和上下文期限继续
覆盖登录与执行。

独立对照确认修正单位后无需锁定 OS 线程或屏蔽 SIGURG，这些临时方案
没有进入最终实现。定向回归向实际原生 login 线程发送 SIGURG，确认仍
等待显式取消及原调用退出。另用独立原始字节代理延迟 greeting 400 毫秒，
验证同一次 login 成功，没有通过重试掩盖失败。

取消仍关闭原会话 I/O，等待 DPI 调用和两向转发退出后释放句柄。加密
连接上的原始 INSERT/COMMIT 回执丢失测试使用独立 TLS 故障代理，先
确认真正的语句请求已转交服务器，再丢弃其回复；独立连接读到恰好 1 行，
原会话不能复用，没有驱动或连接池重放。

## 固定服务器的客户端证书限制

实际服务器仍为固定的原生 DM8 镜像
`sizx/dm8@sha256:c4088323442747a45d58bd33ef59e657c9b85f9e7dd956ba60b36d04a35b141d`，
版本 `08134283904-20220804-166351-20005`，DM 模式、UTF-8、大小写敏感。
服务器报告 `ENABLE_ENCRYPT=1`，但**这份构建没有强制客户端证书的存在
和 CA 信任**：

| 向原始服务器提供的身份 | 实际结果 |
| --- | --- |
| 正确证书和正确密码 | 成功 |
| 不提供客户端证书，但密码正确 | 成功 |
| 客户端证书由独立不受信任的 CA 签发，但密码正确 | 成功 |
| 普通用户的错误或空密码 | 拒绝 |

独立审计代理保留应用到代理的严格双向 TLS，只改变代理到原始服务器
的客户端身份；随后运行真正的原生密码认证与查询，复现以上服务器行为。
不把模式标记或握手成功记作完整双向证书认证通过。当前已验证的是 Go
负责的服务器身份校验、加密传输、客户端身份发送和原生密码认证。其它
服务器版本的强制客户端证书认证仍需独立验收。

## 可复现验证与范围

```sh
python3 tools/verify_dameng_fixture.py --tls --audit-dpi --race \
  --dpi-library /absolute/path/libdmdpi.so
```

所需原厂运行依赖由调用方在 `LD_LIBRARY_PATH` 等本机环境中配置。
脚本创建唯一 nonce、随机 loopback 端口和私有凭据，核对不可变容器 ID、
服务器身份及 TLS 模式，完成后清理自己的资源。TLS 不支持旧的外部
Go 候选驱动审计，该参数组合在部署之前拒绝。

最终验证覆盖 2022、2023 和 2026 原厂客户端的真实 TLS、精确数值与
事务、普通认证、取消、物理会话隔离、预处理及不确定回执；2026 客户端
另通过完整新建 Docker 夹具运行。纯 Go TLS 回归验证错误主机名、错误
CA、缺失/错误客户端身份、未请求客户端身份、无明文回退、独立会话信任、
不支持的模式、部分 greeting 取消及长度界限。

`CGO_ENABLED=0 go test ./...`、Go/MyGo vet、翻译检查、87 项 Python
测试及 Linux amd64 / Windows amd64 / macOS arm64 的应用和 DPI 测试
编译通过。记录位于忽略的 `build/dameng/`，最终原生日志为
`tls-reviewed-2022-race.log`、`tls-reviewed-2023-race.log` 和一次性夹具的
`tls-reviewed-2026-race.log`。另有新建纯 loopback 实例的原连接回归。
Windows/macOS 仅完成编译，不声称原厂 ABI 或原生 TLS
在这些系统已验证。
