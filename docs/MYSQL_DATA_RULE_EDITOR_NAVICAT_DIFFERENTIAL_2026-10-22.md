# MySQL 数据页规则编辑器、列菜单与 Navicat 18 差分（2026-10-22）

仓库 `kang/nyadb`，基线 `afdc9f7`，Go 1.27+，MyGo Native UI v0.6.0，Linux/amd64。仅操作隔离测试容器 `nyadb-mysql-rules-it-20261022`，映射到 `127.0.0.1:34306`；没有连接生产数据库。原版 Navicat 18 仅作为已有授权运行观察资料使用，未修改程序或复制私有源码、品牌资产。无 DDL/DML 写入（测试容器夹具初始化除外）。

- **O**：已授权 Navicat GUI 原版观察（同尺寸 1280×800 截图）。
- **I**：NyaDB Go/MyGo 独立实现并测试。
- **V（有限）**：同一隔离 MySQL 对象的功能或局部几何对照。
- **Unknown**：未取得足够运行/差分证据。

## MySQL 服务层：多规则安全查询（I）

提交 `f093ace`。

- `MySQLDataOptions` 保留兼容的单规则字段，新增 `Filters []MySQLDataFilterRule` 与 `Sorts []MySQLDataSortRule`；现阶段最多支持 **6 条 AND 过滤条件**及 **4 级排序优先级**。不推测原版 OR/嵌套组的行为，也不提供不受限 SQL 输入。
- 筛选运算符 `equal`、`not_equal`、`contains`、`is_null`、`is_not_null`；字段必须来自以参数绑定查询的 `information_schema.COLUMNS`。包含模式仅支持文本型；空值使用 `IS NULL`/`IS NOT NULL`，与空字符串严格区分。
- 各列名以经过校验并安全转义的 MySQL 标识符加入 SQL；数据值全部通过绑定变量传递。拒绝不存在字段、重复排序字段、条件数越界、长度过长及混用单规则/多规则的不一致配置。
- 多级排序采用用户指定的优先级顺序，后附可靠的唯一索引列用于稳定平局排序；没有可靠唯一键或用户排序列允许 NULL 时继续回退 OFFSET 并提示风险。
- Keyset Cursor 使用排序/筛选规则规范化摘要进行范围校验，拒绝更改条件后的旧游标。不提供并发 DML 时的跨页一致性快照保证。

隔离 MySQL 8.4 `nyadb_perf.no_key_entries` 验证了同时使用三条 AND 规则和两级优先排序；模拟驱动验证注入样例保持在绑定参数中，没有流入 SQL 模板。此前 Keyset、分块读取与单条件查询测试仍保持通过。

## MyGo 数据工作区：原生交互（I）

提交 `75a5bfd`。

- 表数据区新增 **可展开/收起的筛选与排序规则面板**。第一条规则和后续 AND 条件可增减；提供字段、运算符和输入值。排序规则按添加顺序优先，可指定升序/降序。仅点击“应用筛选 & 排序”后向服务端提交并返回第一页。
- “清除筛选”重置活动条件但不强制移除当前排序；服务器查询错误时保留上次已知字段元数据及规则编辑器，用户可直接修改或清除错误条件，而不必关闭 Tab。
- 仍使用 MyGo v0.6.0 原生 `ui.Table`：保留列拖动、列宽、横向滚动和单元格选择。列头右键菜单新增**复制字段名称、复制当前页此列的安全预览、隐藏此列、显示/隐藏列子菜单、显示全部列、按当前页拟合列宽、重置全部列宽、显示/隐藏字段类型**。
- 使用可见列→真实结果列索引的映射，隐藏任意列后其他单元格值、复制、选择不会错位。禁止隐藏当前最后一列；恢复列后可继续使用相同真实数据页，列显隐状态按 Tab 隔离。
- 字段类型现在以 `字段名 · 数据类型` 的**单行紧凑形式**显示。MyGo v0.6.0 的原生 `Table` 在 `ui/table.go` 使用固定高度和 `coreText(...).SingleLine()`；当前公开的 `TableColumn` 没有独立 subtitle、两行标题或自定义 header 内容回调。为保留列宽同步、键盘选择、滚动及原生菜单，本轮不使用两个不能共享横向滚动偏移的假表格做双行标题。**双行字段表头仍是明确的未完成差异。**
- 没有改写 MyGo 库或引入 WebView/前端框架。

## 原版 O 与差分矩阵

| 对象 | Navicat 18 O | NyaDB I | 验收 |
|---|---|---|---|
| 筛选/排序入口 | 工具栏“筛选 & 排序”展开规则区域 | 数据区按钮展开内嵌规则面板 | 行为近似，位置与间距非 V |
| 规则编辑 | 筛选、排序独立区，带规则行、增删和应用 | 多条 AND、最多四级排序、应用与清除 | 核心操作 I，通过真实 MySQL；嵌套规则未复刻 |
| 表头 | 字段名第一行、字段类型第二行 | 单行“名称 · 类型” | **未对齐**；受当前原生 Table API 限制 |
| 列头菜单 | 复制、隐藏/显示、适配宽度、字段类型及注释等 | 复制字段/当前页列、显隐、宽度、类型 | 部分功能对齐，未达到完整菜单 V |
| 右信息栏 | 类型、非空、默认值、注释等元数据 | 选中字段类型、NULL/预览、分块进度等 | 信息内容与布局仍存在差异 |
| Keyset | 非原版内部算法对照项 | 原有唯一键安全分页/条件签名校验 | I；不宣称原版使用相同算法 |
| 失效处理 | 原版失败及编辑状态尚待专项采集 | 拒绝条件后仍可编辑、清除、重试 | I；原版 V 尚未验证 |

本轮的 1280×800 NyaDB 真实 Linux GUI 流程：启动独立 Xvfb → 新建临时 MySQL 连接档案 → 连接授权隔离 MySQL → 展开 `nyadb_struct_a` → 双击 `child` → 展示 3 条真实行数据 → 右键 `id` 列头 → 点击隐藏 `id` 列 → 验证剩余真实列值仍按表头映射。真实 GUI 截图与原版截图同尺寸；未进行逐像素自动图像指标分析，不宣称全局 V。

## 后续优先级

1. 优先为 MyGo Native Table 设计与验证支持 **标题+副标题两行的表头 API**，要求滚动、拖动调整列宽、排序和 HeaderMenu 继续共享同一列布局；在上游能力就绪之前不制造假双行表头。
2. 将筛选规则升级为经过规格验证的 OR/AND 组及括号优先级，并为各类型列提供更完整的操作符和 NULL 逻辑；不要把本轮 AND-only 误称为完整 Navicat 等价。
3. 继续取证原版“显示注释”、快捷键、列宽自动适配和菜单禁用状态，做可复现差分测试；右侧字段信息增加字段默认值和注释等真实元数据。
4. 对多表 Tab 状态恢复、保存列布局、筛选配置切换以及超过屏幕宽度后的表头同步做桌面专项测试。

本轮验证只涉及经过授权的隔离数据。一次性容器与新启动的 Xvfb/GUI 在收尾时停止，原有 Navicat 研究桌面不强制销毁。
