# MariaDB 正式接入（2026-11-06）

MariaDB 现在是独立连接类型，使用 `mariadb` 配置标识和 `mariadb://` URI，默认 TCP 端口为 3306。客户端复用现有 MySQL 驱动；连接目录、原生窗口图标、导航筛选、凭据、会话和文档保留 MariaDB 的产品身份。

## 功能与兼容性

支持 MariaDB 10.11 及以上。会话发布前读取 `VERSION()`，拒绝其他数据库产品和低于基线的版本；失败或取消会关闭本次捕获的连接池。直接连接测试、隧道测试与真实会话遵守同一版本规则。

SQL、数据库/对象元数据、函数/存储过程/事件定义、共享数据网格、分页与键集游标、过滤排序、完整字段读取、数据编辑、事务、导入导出、分析、表/视图设计、表复制、备份恢复和维护复用已有功能模块。连接支持验证证书及主机名的 TLS，也复用现有 SSH 与 HTTP/WebSocket 隧道。隧道安全行为仍由 transport 的测试覆盖；本轮 MariaDB 容器验证使用真实 TLS 直连。

连接表单支持高级选项、连接配置文件、初始 SQL、临时密码及系统凭据库的保存/回滚。配置继续使用现有 SQLite 列及 MySQL 家族高级设置 JSON 格式；没有新增存储迁移。已有 MySQL 配置不会被自动改成 MariaDB，现有数据布局键也保持兼容。

表设计快照包含产品身份，执行器验证它与原会话一致。MariaDB 的 CHECK 删除生成 `DROP CONSTRAINT`，MySQL 保留 `DROP CHECK`。重新读取后的整数显示宽度、BOOLEAN→TINYINT、JSON→带 `json_valid` CHECK 的 UTF8MB4 二进制排序规则 LONGTEXT 可以验证为等价；验证仍检查实际类型、符号、ZEROFILL、约束目标和排序规则。任意 LONGTEXT 或不同 CHECK 不会被当作 JSON 等价定义。

账号/角色管理未开放：现有实现使用 MySQL 的账号系统表与角色语义，运行时接口也明确拒绝 MariaDB 账号操作。MySQL 的 CHECK ENFORCED 和索引 VISIBLE/INVISIBLE 语义在 MariaDB 设计器中明确拒绝。未知字段属性或完整定义保持原文并限制编辑；不确定的 DDL/提交结果保留草稿，禁止自动重放。视图和程序定义继续使用保守的完整定义验证，未识别的服务端改写不会被宣称为已验证。

## 真实数据库验证

`tools/verify_mariadb_fixture.sh` 创建独立、随机命名、仅绑定回环地址的容器及临时证书，并为专用测试账号设置 `REQUIRE SSL`。它默认验证三个 LTS 分支，退出时清理自己的容器和证书。测试表及数据位于专用 `nyadb_maria_it` 数据库。

| 实测版本 | 运行时验证 | 原生工作台验证 |
| --- | --- | --- |
| 10.11.19 | TLS、SQL、元数据、精确值、分页/字段读取、编辑冲突、事务、EXPLAIN、导入导出/分析、设计/复制、备份恢复、维护、取消及会话撤销 | 界面连接、独立筛选、真实网格读取/保存、SQL 执行、断开后的文本保留及数据文档清理 |
| 11.4.13 | 同上 | 同上 |
| 11.8.9 | 同上 | 同上 |

运行时测试经过 dbruntime 的公开代际接口，验证旧 SQL 租约、数据绑定和管理绑定不会路由到重连后的会话。备份恢复验证高精度 DECIMAL、二进制字节和完整长文本；数据页同时检查 NULL 与空值、生成字段只读和乐观冲突。

可重复运行：

```sh
tools/verify_mariadb_fixture.sh
# 或只验证一个分支：
tools/verify_mariadb_fixture.sh 10.11
```

日志输出在忽略目录 `build/mariadb/*-integration.log` 和 `*-workbench.log`。中英文连接表单和真实网格截图同样位于 `build/mariadb/`。

## 回归检查

连接服务测试验证 URI 的独立身份、TLS 参数、秘密分离、活动配置解析和跨引擎选项拒绝。持久化测试关闭并重开配置数据库，验证 MariaDB 主/备用配置和旧 MySQL 空高级配置的兼容性。编辑器测试验证凭据恢复、失败保存回滚、异步探测和错误脱敏；导航/原生窗口测试验证品牌图标、独立类型及中英文入口。

完整检查使用 `CGO_ENABLED=0 go test ./...`、`CGO_ENABLED=0 go vet ./...`、`go tool mygo vet`、`go tool mygo i18n check` 和 `CGO_ENABLED=0 go build ./cmd/nyadb`。生命周期相关包另使用 `CGO_ENABLED=1 go test -race`；Go 的 race 检测需要 CGO。

以上检查全部通过。完整生命周期包列表的 race 检测通过；最后新增的 MariaDB 规则和入口还通过了专项 race 检测。使用带 Pillow 的系统 Python 执行 `/usr/bin/python3 -m unittest discover -s tests -v`，64 项视觉工具测试全部通过。截图已检查，测试容器和临时证书均已清理。
