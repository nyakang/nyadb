# DuckDB 接入与验证（2026-11-06）

NyaDB 已增加独立 DuckDB 连接类型、配置持久化、文件连接表单、运行时 provider 和共用数据工作区。DuckDB 不通过 SQLite 模拟；真实查询、事务和保存由官方 DuckDB 执行。连接选择器里的其他候选类型不代表已有运行时适配。

## 安装与使用

需要官方 **DuckDB 1.4.4** 动态库。应用通过 purego 调用 C API，Go 构建仍支持 `CGO_ENABLED=0`；动态库必须单独安装或随应用分发。

```bash
python3 tools/install_duckdb_runtime.py
CGO_ENABLED=0 go run ./cmd/nyadb
```

创建 DuckDB 连接，选择现有数据库文件；取消“现有数据库文件”后，可在连接时创建文件。输入 `:memory:` 创建临时数据库。文件连接默认要求已存在，默认 schema 为 `main`，内存限制 512 MiB，工作线程 4，后台/SQL 连接上限各 8。只读文件连接始终要求文件存在；只读内存连接被拒绝。

支持 `duckdb:///:memory:` 和 `duckdb:///absolute/path/data.duckdb?read_only=true` URI。DuckDB 不使用服务器地址、端口、用户名或密码。配置保存在已有版本化 engine-options envelope 中，不增加数据库迁移，也不改变已有引擎的持久化格式。

加载器按以下顺序查找运行库：连接指定的路径、`NYADB_DUCKDB_LIBRARY`、可执行文件旁或 `runtimes/duckdb`、macOS `.app/Contents/Frameworks`、Go `os.UserCacheDir()` 下的 `NyaDB/duckdb/v1.4.4/<os>-<arch>`、受支持的系统库目录。显式路径或环境变量指定后不回退到其他库。

安装器验证发布 ZIP 和解压后库的 SHA256；加载器在加载前再次校验库，并验证版本。只接受清单中的官方原始库；自建、其他版本或重新签名改变内容的库不在支持范围内。此次旧 x86 测试 CPU 在加载官方 2.0.0 时发生非法指令，1.4.4 已实际验证。这里不宣称兼容 DuckDB 2.0 或所有 CPU。

## 能力与边界

| 功能 | 已实现 | 边界 |
| --- | --- | --- |
| 连接与导航 | 文件/内存、只读、schema、表/视图、序列、用户 macro、注释和完整定义 | 导航限定初始 catalog；SQL 中的临时表和 `ATTACH` 不自动扩展导航树 |
| 结构 | 列、类型、默认值、生成列、PK/UNIQUE/FK、独立 ART 索引和表达式 | 只读查看；表达式索引不能充当可编辑行键 |
| SQL | 独立物理会话、批量语句、dollar/E strings、嵌套注释、取消、补全、格式化、JSON EXPLAIN | 最多 1024 条语句；缓存 1000 行/8 MiB，普通单元格预览 64 KiB；超限明确标记 |
| 数据网格 | 唯一共用 State/Document/grid、LIMIT/OFFSET、参数化筛选、排序、计数、字段检查 | 没有 keyset；无可靠键的分页不保证跨次读取稳定 |
| 编辑与事务 | 插入/更新/删除、DEFAULT、RETURNING、两种原值验证、保存后读回、显式提交/回滚 | 需要非空、非生成、可比较的 PK/UNIQUE 键；视图、生成字段和不支持的类型拒绝编辑 |
| 大字段 | 1024 字符/字节显式分块、完整行读取及 1 MiB 编辑边界、保留截断状态 | SQL 原生读取单值最多 8 MiB；嵌套值有深度/条目预算；超限报错，不静默丢行 |
| 导入/导出 | typed export、JSONL，共用 UI 的 CSV 等格式；内存/流式 append 原子导入 | 导入限已有可编辑表；不支持新建表、upsert、继续忽略错误或扩展插入模式 |
| 分析 | 非 NULL distinct/singletons/modes、min/max、mean/stddev、有界分布 | 数值聚合使用 DuckDB 的精度规则，浮点统计不能视为任意精度；不提供完整分布/median |

精确 DECIMAL(38,20)、HUGEINT/UHUGEINT/UBIGINT、BLOB、含 NUL 的 VARCHAR、UUID 和纳秒时间戳已真实验证，不先转为 float64。LIST/STRUCT/MAP/ARRAY/UNION/ENUM 以有界文本显示。DuckDB 1.4.4 的 C API 没有正确公开 TIME_NS 的类型 ID，BIT/BIGNUM 的私有向量布局也未绑定：网格/导出由服务器 CAST 为文本；直接 SQL 返回这些原生类型时明确要求显式 `CAST(... AS VARCHAR)`。这些类型的网格编辑不开放，TIME_NS 可通过服务器转换按时间值处理。

不开放表/视图设计器、对象管理对话框、备份/恢复、维护、账户管理、隧道及 keyset。用户仍可在 SQL 工作区执行 DuckDB 支持的语句；自动安装/自动加载扩展默认关闭。

## 生命周期与写入安全

每个 profile/session 保持原始 catalog/schema 身份，公共 generation 由 dbruntime 发布。SQL 文档使用独立连接，SQL 池和后台池共享同一原生 database instance。同一规范文件路径的连接共享实例；只读、内存或线程设置不一致时明确拒绝。一个 profile 关闭不释放另一个 profile 仍使用的实例；正在关闭的物理连接持有实例引用直到取消完成。

事务使用 DuckDB 的 MVCC snapshot 语义，不宣称 serializable。保存以完整 typed values 或 SHA256 fingerprints 验证原值和元数据。冲突与不确定提交保留草稿，不自动重放。驱动中断限定到原物理连接，并等中断回调确认后释放；SQL 错误或取消撤销原租约，必须显式恢复。断开保留 SQL 文本，并释放该连接的数据/对象文档。`:memory:` 在最后一个所属连接释放后销毁；重新连接不会恢复数据。

服务器诊断可能包含 SQL 字面量/绑定值，运行时对公开状态和导入记录使用脱敏错误。测试只使用 `testing.T.TempDir()` 临时文件与固定测试值，不读取用户数据库或凭据。

## 复现验证与打包

```bash
python3 tools/verify_duckdb_fixture.py
# Go race detector 需要本机 C 编译器；DuckDB binding 本身仍不使用 CGO。
python3 tools/verify_duckdb_fixture.py --race

python3 tools/package_duckdb.py --target linux-amd64
python3 tools/package_duckdb.py --target windows-amd64
python3 tools/package_duckdb.py --target darwin-arm64
```

portable 打包工具输出 `build/duckdb/package-<target>/`，包含应用、对应运行库、MIT license 和来源记录；分发整个目录。其他 64 位清单目标也可构建。普通 `go tool mygo build` 不自动把下载库写入其归档；可先安装用户缓存运行库再使用该包。制作 macOS 原生 `.app` 时，将验证过的库安装到 `Contents/Frameworks`，并保留许可证和来源记录。

已实际验证的环境是 Linux amd64、Go 1.27.3 和官方 DuckDB 1.4.4。原生 fixture 覆盖 typed values、回滚、中断确认；adapter fixture 覆盖 schema/结构、两种保存验证、冲突、字段分块、超限、流式导入失败回滚、EXPLAIN、共享文件与在执行查询时关闭 session；MyGo headless tester 使用真实数据库验证连接、共用网格保存、SQL、断开恢复并生成截图。截图是 headless 渲染，不是桌面窗口证明。

Linux amd64、Windows amd64 和 macOS arm64 已完成 `CGO_ENABLED=0` 编译。Windows/macOS 尚无本地真实运行验证；CI 配置会下载验证过的运行库，在三种宿主系统上执行 fixture、静态检查和构建。Linux 的全量 Go 测试、Go vet、MyGo vet、翻译检查、工作区整体 race 和最新 DuckDB native/adapter/UI 专项 race 均通过。翻译检查覆盖 1929 条消息，Python 工具测试共 67 项通过。

此外，在独立 Xvfb/GTK 软件渲染环境中启动了实际 Linux 应用，未指定运行库环境变量，确认可执行文件旁的运行库自动加载；通过原生窗口连接、展开 catalog/main、打开网格、F2 编辑并保存、执行 SQL。进程退出后独立重读文件，保存文本和完整 `9007199254740993.12345678901234567890` 数值均一致。此原生窗口验证不代表物理桌面、GPU、IME 或多显示器测试；截图保存在 `build/duckdb/native-smoke/native-saved-grid.png` 和 `native-sql-result.png`。

本地验证截图与日志位于忽略目录 `build/duckdb/verification/`，不提交运行库或大二进制。`build/duckdb/verification/delivery.json` 记录检查结果、编译产物和原生截图摘要。DuckDB 发布来源、库/归档摘要及 MIT license 保存在 `resources/duckdb/`；黄色鸭图标由 NyaDB 自绘，来源记录在连接图标 manifest 中。
