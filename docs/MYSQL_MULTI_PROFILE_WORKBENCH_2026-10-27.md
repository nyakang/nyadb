# NyaDB 多连接会话工作台：按档案隔离的导航与异步状态

2026-10-27，连接资产导航阶段三。

## 目标和边界

消除工作台在连接 B 时自动关闭连接 A 的单会话限制。MySQLSessionManager 服务层早已有以 `ProfileID` 为键的连接池、代际保护和单连接断开机制；本轮独立实现的是 Go/MyGo 工作台的 **会话槽位**。不操作 Navicat 原版，不使用生产数据库，不复制 Navicat 资源。

## 设计

1. 新增 `mysqlSessionWorkspace` 存储每个已打开档案的 UI 状态：会话取消与一次性结果通道、generation、连接状态、数据库列表、对象缓存/错误/请求、选择、对象行状态及活动导航定位目标。非活动槽位存放于 `mysqlWorkspaces[ProfileID]`，当前槽位继续暂时由现有 State 字段承载，以分阶段迁移原生界面与表格流程。
2. `activateMySQLProfile(id)` 将上一槽位保存并恢复目标槽位；**不产生连接/断开/数据库查询**。新档案没有运行会话则显示未连接。真实建连仍仅由 `startMySQLSession` 驱动；重新连接只断开同一 `ProfileID`。
3. 原生 Outline 的已连接状态、数据库列表、已加载表/视图元数据均按 `ProfileID` 获取，防止两个连接有同名数据库时串用缓存。对尚未支持的对象分类继续明确禁用，不伪造服务器内容。
4. 连接、数据和表结构页签的异步结果必须先验证自己的 `ProfileID` 和请求代际。停放连接的表结构、数据、字段信息与大字段读取结果在切回前保留在原有缓冲通道中，而不是用当前连接的代际错误丢弃；重新选择其页签会先恢复相应槽位。
5. 停放连接的建连/数据库列表完成后在 UI 线程消费结果，无需重新选中即可更新树状态；数据库列表刷新完成后在重新激活时清理过期的对象缓存和同一连接的数据库页签。
6. 删除档案、断开单个连接或“关闭所有连接”均按连接身份处理。断开连接 A 仅取消 A 的请求、关闭 A 的 MySQL 数据与表结构页签并调用 `manager.Disconnect(A)`，保留其他连接和无关 SQL/设置页签。程序退出继续调用 manager.Close 清理资源。
7. 不持久化工作台会话或凭据；凭据仍由已有密钥库／当前内存输入提供。避免因切换到另一尚未连接的档案而泄露前一档案的内存密码草稿。

## 回归用例

`mysql_multi_profile_navigation_test.go` 使用隔离 SQLite 连接档案与 MyGo `ui.NewTester`，提供不访问网络的 session opener/list mock，覆盖：

- 连接 A→连接 B 时 A 保留连接态；切回时恢复各自的数据库、对象缓存和选中行；
- 相同数据库名称下的表元数据不交叉；
- 关闭停放连接 A 后 B 继续可用，关闭全部会话清理所有槽位；
- B 刷新数据库结构不会删除 A 的数据/结构页签；
- A 的异步握手在用户已切到 B 时完成，A 状态仍独立更新；
- 打开 A 旧表结构页签自动切回 A 会话；
- 原来的单连接密码、重连提示及无生产连接测试必须继续通过。
