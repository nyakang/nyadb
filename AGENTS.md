# Repository Guidelines

## Project Structure & Module Organization

NyaDB is a Go desktop database workbench using MyGo UI. `cmd/nyadb/` is the development entry point; root `main.go` supports MyGo tooling. `internal/bootstrap/` wires startup, `internal/ui/shell/` contains workbench views and interaction state, `internal/ui/connectioncatalog/` owns the connection type chooser, `internal/ui/connectioneditor/` owns connection forms and editing state, `internal/ui/navigation/` owns the connection navigator, `internal/ui/sessionbrowser/` owns session workspaces and metadata jobs, `internal/ui/sqlworkspace/` owns SQL documents and execution, `internal/ui/dataworkspace/` owns complete data documents and their information panels, `internal/ui/objectworkspace/` owns object lists, table actions, read-only structures and program definitions, and `internal/ui/theme/` defines appearance and shared icon caches. Connection models, validation, and configuration services live in `internal/services/connections/`; authenticated MySQL sessions, SQL execution, metadata, and data operations live in `internal/services/mysql/`. SQLite profile storage, application preferences, and migrations live in `internal/storage/localdb/`.

Both `localdb` and the MySQL service depend on connection models; `connections` must not depend on storage, database drivers, or UI. Bootstrap and shell compose these packages. Import the MySQL service as `mysqlsvc` and the MySQL driver as `mysqldriver`.

`connectioncatalog` owns chooser search, filters, presentation, selection and in-session recents. Shell hosts its view and opens the connection editor through selection callbacks. The chooser must not depend on shell, storage or the MySQL runtime service. Shared brand bitmap caches belong to theme; callers must not modify their maps.

`connectioneditor` owns raw form inputs, alternative configurations, temporary secrets, vault save/rollback and asynchronous connection checks. Configuration services, vaults, MySQL validation/testing and host callbacks are injected. It must not import shell, storage or database drivers/runtime services. Shell owns native windows, chooser navigation, saved-profile list refresh and requests real session invalidation through `sessionbrowser`; bootstrap-facing picker methods remain on shell and forward to the editor.

`navigation` owns qualified node keys, profile/group snapshots, tree selection and disclosure, search/engine/star filters, temporary filter restoration, inline group editing and navigation icons. It consumes read-only session metadata and workbench callbacks; it must not import shell, storage or MySQL runtime services. Shell supplies those callbacks in the existing profile view and coordinates profile selection, object actions, context-menu commands and documents with `sessionbrowser`. A database's opened state belongs to its session and remains separate from tree disclosure. Single click selects an unopened database; explicit open, double click or Enter schedules metadata.

`sessionbrowser` owns stable per-profile workspaces, session/password drafts, database and object caches, opened database state, cancellation and monotonic session generations. Session/database/object loaders and host callbacks are injectable; stored credentials are read through a callback. It may depend on the MySQL service and MyGo presentation state, but must not import shell, navigation, storage or database drivers. Private buffered result channels are consumed only on the UI thread. Parked handshakes can finish without changing the active profile; parked object reads are consumed when that profile returns. Reconciliation cancels a read only when its database is removed, independently of the selected row. Shell coordinates unsaved-document guards, navigator disclosure and tab cleanup; object views/actions belong to objectworkspace; its exported session-close entry point remains compatible with bootstrap.

`sqlworkspace` owns SQL editors, shared editor/result split position, selection/caret dispatch, execution and cancellation, results, asynchronous preconnect and physical session leases. Runtime/connection state and workbench callbacks are injected; it must not import shell, navigation, sessionbrowser, storage or database drivers. Workers capture immutable request values and their owning lease; only the UI thread consumes private buffered channels. Cancellation waits for driver acknowledgement. Disconnect keeps SQL text and requires explicit recovery of the original profile without replaying SQL. Shell owns tab selection/profile activation and forwards terminal cleanup.

`dataworkspace` owns immutable qualified data documents, paging/cursors, filtering/sorting, grid selection and column layout, editing/drafts, clipboard/export, leave decisions and table/field information. Runtime methods, active session snapshots, profile lookup, preferences and host callbacks are injected; it must not import shell, navigation, sessionbrowser, storage or database drivers. Workers capture deep copies of cursor boundaries, row identities, fingerprints, edit maps/bytes and verification requests. Private buffered channels are consumed on the UI thread; parked reads and writes wait for activation. Generation mismatch settles loading without replacing cached data; uncertain or incomplete commits retain drafts and prohibit replay. Save cancellation waits for executor acknowledgement. Page, count and bounded field reads have separate cancellation scopes; field reads remain explicit and limited to 1024 characters/bytes, complete editing to 1 MiB. Close unregisters documents, revokes requests and releases caches/callbacks. Layout keys and stored formats remain compatible.

`objectworkspace` owns per-profile object-list selection, scrolling, column layout, list filters and toolbar categories, object menus, table-action dialogs, structures and program definitions. Database changes reset list selection/filter/scroll while retaining columns; toolbar categories remain independent of list filters. Read-only browser/session snapshots, structure loaders, table executors and host callbacks are injected; it must not import shell, navigation, sessionbrowser, dataworkspace, storage or database drivers. Table completion carries the original profile, generation, database, table, destination and operation. Parked table completion is delivered for that original profile; shell coordinates cache invalidation and data/tab changes. Structure requests use private buffered channels and generation checks; refresh/cancel/close revoke old work. Program snapshots remain synchronous/read-only, reject unsupported or unqualified identity, retain the full definition and display at most 500 lines. Close is idempotent; CloseAll also cancels table operations and releases browser/modal state. Object and field model-to-property conversion stays in its feature module; generic stateless property rows and empty table headers belong to theme.

Shell owns native windows, chrome, splitters, tabs, profile management and cross-module coordination. A tab contains identity/title/type and module documents only. Qualified identity lookup, activation, leave guards, disposal and batch removal live in the existing workbench code. Closing inactive tabs preserves the active document ID; database pruning and table changes use the original profile identity. Disconnect preserves SQL text and explicit recovery, while disposing scoped data/object documents. Exit releases all requests and SQL leases. Preview has private tree/grid/selection/filter state and does not mutate live navigation or sessions; settings state stays beside its page. Bootstrap-facing constructors, views, picker/research-icon methods, layout preferences, workbench-close checks and session-close interfaces remain compatible.

Go tests sit beside source files. `internal/assets/` contains embedded icons, `resources/` contains artwork, and `locales/` contains translations. `docs/` records design and verification; `tools/` and `tests/` contain utilities and Python visual-comparison tests. Builds and research belong in ignored `build/` and `temp/` directories.

## Build, Test, and Development Commands

Use Go 1.27.1 or later and the MyGo fork pinned in `go.mod`. Linux requires GTK 3 runtime libraries (`libgtk-3-0`) and a desktop session for native execution.

- `go mod download`: fetch dependencies.
- `go run ./cmd/nyadb`: launch locally.
- `go tool mygo doctor` / `go tool mygo dev`: diagnose prerequisites or start development mode.
- `go test ./...`: run Go tests, including headless UI tests.
- `go vet ./...` and `go tool mygo vet`: run static and UI checks.
- `go build ./cmd/nyadb`: compile; `go tool mygo build`: package into `build/`.

CI runs tests, checks, and compilation with `CGO_ENABLED=0` on Linux, Windows, and macOS.

## Coding Style & Naming Conventions

Format Go with `gofmt` (tabs). Use lowercase packages, exported `PascalCase` identifiers, unexported `camelCase` identifiers, and descriptive snake_case filenames. Keep persistence, services, and views in their respective packages. Edit translation JSON catalogs, then run `go tool mygo generate` and `go tool mygo i18n check`; do not hand-edit `locales/catalog_gen.go`.

## Testing Guidelines

Use Go's `testing` package, `*_test.go` files, and `TestBehavior` names; UI tests use MyGo's `ui.NewTester`. No numeric coverage threshold is configured. Cover changed behavior and migration compatibility. Python visual-tool tests require Pillow: `python3 -m unittest discover -s tests -v`. MySQL integration tests require disposable fixtures and explicit `NYADB_MYSQL_*_IT` flags; consult the relevant tests and docs before enabling them.

Configuration and service tests use `connections_test`; SQLite persistence and legacy profile decoding tests live beside `localdb`, and MySQL runtime tests live beside the MySQL service. Chooser state and view tests live beside `connectioncatalog`; editor form, configuration, credential and async-check tests live beside `connectioneditor`; navigator filtering, node identity, category order, inline editing, virtualization and icon tests live beside `navigation`; workspace identity, session generations, metadata refresh/cancellation and late-result tests live beside `sessionbrowser`; SQL statement, result, cancellation, preconnect and recovery tests live beside `sqlworkspace`; paging, grid/layout, editing safety, copy/export and table/field inspector lifecycle tests live beside `dataworkspace`; object filters/menus, table actions, structure lifecycle and program snapshot/definition tests live beside `objectworkspace`. Shell keeps native-window, navigation/workbench wiring and real-session integration tests. Disposable MySQL SQL fixtures live in `internal/services/mysql/testdata/`. Legacy-data fixtures hold their database handles explicitly rather than exposing them through production storage APIs. For focused regression checks, run `go test ./internal/services/connections ./internal/storage/localdb ./internal/services/mysql ./internal/ui/shell ./internal/ui/connectioncatalog ./internal/ui/connectioneditor ./internal/ui/navigation ./internal/ui/sessionbrowser ./internal/ui/sqlworkspace ./internal/ui/dataworkspace ./internal/ui/objectworkspace ./internal/ui/theme`; run the same package list with `go test -race` for lifecycle and concurrency changes.

## Commit & Pull Request Guidelines

Follow history's `type(scope): imperative summary` convention, e.g. `fix(mysql): preserve nullable field metadata`. Use scopes such as `ui`, `theme`, or `deps`. PRs should explain behavior changes, link relevant issues, report validation, and include screenshots for visible UI changes.

## Configuration & Assets

Keep credentials out of profiles, logs, and commits. Configuration lives under `os.UserConfigDir()/NyaDB/config.sqlite`. Preserve asset licenses and provenance manifests; keep proprietary research assets in ignored local directories.
